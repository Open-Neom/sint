# SintApp: revisión y validación del 21 de septiembre de 2026

Estado: preview local `1.7.0-dev.1`, sobre SINT `2b3db47d`, con cambios sin
publicar. Esta revisión completa la evidencia pendiente de las pruebas de
Cyberneom/Gigmeout en Android y web y de Giglab en macOS.

## Qué faltaba

1. **Pruebas específicas de SintApp.** La fachada ya existía, pero no había
   regresiones que comprobaran sus dos hosts, la selección de plataforma y la
   continuidad del controlador al cambiar temas.
2. **Propagación de temas declarativos.** Una actualización de `materialTheme`
   desde el padre no llegaba a la configuración persistente del root. Ahora se
   actualizan los campos de diseño, incluso cuando vuelven a `null`, conservando
   el root, el router y la propiedad de los controladores. Un rebuild sin cambios
   declarativos conserva las actualizaciones imperativas.
3. **Overlays y Material dentro de Cupertino.** Se añadió un ScaffoldMessenger
   standalone bajo el host Cupertino; los diálogos consultan las localizaciones
   correctas y capturan temas heredados. Los bottom sheets usan una ruta
   standalone con el seguimiento de ciclo de vida de SINT.
4. **Cierre de snackbars.** Quitar un overlay sin animación dejaba su temporizador
   activo. Ahora también se cancela en ese camino.
5. **Resolución limpia de dependencias.** Una instalación nueva elegía
   `material_ui 1.3.0` / `cupertino_ui 1.1.0`. Sus manifiestos permiten Flutter
   3.44, pero su código usa `foundation.awaitNotRequired`, no exportado por ese
   SDK. Se reprodujo un error de compilación con Flutter 3.44.8 y se acotaron las
   versiones a Material `<1.3.0` y Cupertino `<1.1.0`. La resolución verificada
   usa `1.2.0` / `1.0.2`; no se modificó la caché de paquetes.
6. **Documentación y CI coherentes.** Había textos que aún describían SintApp
   como una propuesta no implementada y una tarea CI con Flutter 3.32,
   incompatible con el nuevo mínimo. Las guías describen la preview, las APIs
   tipadas, los límites del bridge y los requisitos SDK. CI apunta a 3.44.4 y
   Flutter 3.x estable; editar el workflow no equivale a haberlo ejecutado.
7. **Evidencia real de las aplicaciones.** Algunos logs anteriores estaban
   vacíos o incompletos. Se repitieron builds y se registraron sus resultados;
   los artefactos antiguos no se contaron como validación del código actual.

SDK explícito: `/Users/serzen/src/flutter/bin/flutter`, Flutter **3.44.8 stable**
(`058e0af2c2`), Dart **3.12.2**. Se resolvieron nuevamente las dependencias del
paquete y de `performance` con ese SDK antes de ejecutar las pruebas.

| Comprobación | Resultado |

| `flutter test --no-pub --exclude-tags=benchmark` | 364 pruebas aprobadas antes de la revisión final de bottom sheets. |

Los logs están en `build/sint-app-qa/2026-09-21/`: `stable-analyze-final.log`,
`stable-correctness.log`, `stable-performance-app-tests-bounded.log` y los logs

anteriores ejecutados con un comando Flutter master y una configuración de

Estas pruebas no son mediciones de rendimiento. No se atribuye ninguna mejora
de benchmarks a la separación de bibliotecas de diseño.

## Aplicaciones piloto

| Aplicación y destino | SDK del build | Resultado |
| --- | --- | --- |
| Cyberneom web JavaScript release | Flutter 3.48.0-1.0.pre-228 / Dart 3.14 dev | Aprobado tras actualizar únicamente la dependencia de cámara y los ajustes requeridos por el SDK. |
| Gigmeout web JavaScript release | Mismo SDK master | Aprobado, 88.7 s. |
| Giglab example macOS debug | Mismo SDK master | Aprobado tras corregir el import de GlobalWidgetsLocalizations; se repitió después de los ajustes del root. |
| Cyberneom Android debug | Flutter 3.44.8 stable | En verificación. |
| Gigmeout Android debug | Flutter 3.44.8 stable | En verificación. |

Cyberneom fijaba `camera_web 0.3.5+4`, que falla con Dart 3.14 por anotaciones
`@JS` inválidas en constructores de extension types. La actualización focal a
`0.3.5+6` contiene el arreglo publicado en `+5`. Gigmeout ya utilizaba `+5`.

Giglab usaba `material.GlobalWidgetsLocalizations`; esa clase se importa de
`flutter_localizations`, sin el prefijo Material. El arranque macOS previo
inicializó Flutter, Hive, controladores y audio, pero un proyecto local guardado
referenciaba audio inexistente (`SoLoudFileNotFoundException` / AVFoundation
`-11800`). Compilar no demuestra que todo ese proyecto guardado pueda ejecutarse.

Los intentos Android con Flutter master fallaron en la validación de Gradle/AGP
antes de compilar Dart. Se eligió el SDK estable instalado para la comprobación
principal; no se desactivó la validación ni se ampliaron actualizaciones de AGP y
Kotlin para satisfacer un SDK preliminar.

Los builds web aprobados son JavaScript, con `--no-wasm-dry-run`; no certifican
Wasm. No se desplegó ni se arrancaron las aplicaciones conectadas a Firebase.
Los builds Android y el de Gigmeout web usan los defines de emuladores y bloqueo
de Firebase de producción en compilaciones no release.

## Qué queda antes de declarar estable 1.7.0

- Ejecutar CI en el mínimo declarado exacto y en el estable actual; esta sesión
  comprueba 3.44.8 y registra por separado los builds con master.
- Completar smoke y revisión visual de las aplicaciones, navegación/deep links,
  botón atrás de Android y temas de alto contraste/sistema. Los widget tests de
  plataformas no sustituyen pruebas sobre cada dispositivo.
- Mantener el bridge durante la migración de módulos compartidos. `defaultDialog`
  aún fabrica widgets SDK y `snackbar(mainButton:)` acepta `TextButton` SDK;
  `rawSnackbar(mainButton:)` admite `Widget`. No se afirma una migración completa
  de todas las APIs públicas a standalone.
- Resolver la fuente `CupertinoIcons` ausente que advierte Cyberneom web y los
  archivos de audio faltantes del proyecto guardado de Giglab si se usan en QA.
- Revisar los límites temporales de las dependencias cuando exista una solución
  upstream compatible con el mínimo SDK.

`SintApp.theme` lleva la advertencia de deprecación solicitada. Las clases
legacy existentes continúan disponibles; sus objetos no se convierten a los
tipos standalone. La [guía de migración](../../MIGRATION_DESIGN_SYSTEMS.md)
explica el camino gradual y sus límites.
